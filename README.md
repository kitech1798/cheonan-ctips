# 천안 교통 아틀라스 C-TIPS

천안시 AI·데이터 활용 공모전 출품작. 사고·인구·고령·버스·정류장·교통카드 **8종 공공데이터**를
결합해 **어느 동네가 아니라 어느 지점부터** 손댈지 답하는 교통정책 도구.

**Cheonan Traffic Issue Prescription System**

## 구성 (자체완결 단일 페이지 · 4탭)
- **🗺️ 지도** — 9개 지표 색지도(위험도·대중교통·고령·규모 대비 사고 등) + 노선 265 · 정류장 2,489 · 사고 다발 지점 + 동 클릭 진단서
- **📊 통계** — KPI · 대중교통 이용 프로파일(시간대·이용자·지역) · 문제별 랭킹 · 31개 전체 진단표
- **💡 개선안** — 데이터 발견 5가지 · 우선 개선 대상 **31개 전수** · 유형별 처방 · 정책 사업화 보드 · *접힌 검증 상세(대조군 비교·모형 평가·민감도)*
- **📋 실행 목록** — ⭐사고 개선 대상 **지점**(지점명·심각도·권장 조치·난이도) · 버스와 사고가 **같은 자리**인 정류장 · 정류장 조치 대상

## 이 도구가 답하는 것
예산은 행정동이 아니라 **교차로·횡단보도·정류장**에 집행된다. 그래서 "어느 동이 위험하다"에서 멈추지 않고
지점명·피해규모·주변 정류장·권장 조치를 한 줄에 담았다.

사고 자료와 교통카드를 좌표로 겹쳐야만 나오는 목록 — **버스와 사고가 같은 자리에서 일어나는 정류장 84곳**.
쉘터와 횡단보도를 하나의 사업으로 묶을 근거가 된다.

## 정직 표기
- 사고 = 도로교통공단이 지정한 **다발지역** 건수. 천안 전체 사고(연 3,368건)와 세는 기준이 다르다.
- 수치는 각 지점이 **마지막으로 지정된 해**의 값. 여러 해를 더하지 않는다(다발지역은 누적 기준 지정).
- 같은 현장이 유형·표기별로 나뉘어 보고되므로 **지점명과 좌표로 한 현장으로 합쳤다** — 합치지 않으면 사망자를 두 번 센다.
- 정류장부하는 **이용 집중도**이며 공급부족 확정이 아니다(정차 노선 수·운행 횟수 미반영).
- **사고 건수를 예측하지 않는다** — 시간분할 검증에서 "작년만큼 난다"는 단순 가정에 졌기 때문.
- **개선 효과를 %로 약속하지 않는다.** 사업별 감소율을 뒷받침할 자료가 없어, 자료 안에서 산술로 확정되는 것만 말한다
  — 상위 지점이 그 동네 사고의 몇 %인가, 규모만큼까지 내려오면 몇 건이 남지 않는가.
- **소관 부서는 표기하지 않는다.** 시 조직·업무분장을 확인할 자료가 없어, 추정해 적는 대신 비워 뒀다.
- 여기 없는 지점이 안전하다는 뜻이 아니다. 다발지역으로 지정될 만큼 사고가 모이지 않았을 뿐이다.
